# Changelog

Every release of the `prismpm` crate and the SDK has an entry here, newest first.
The `prism-code` npm package has its own: [sdk/npm/prism-code/CHANGELOG.md](sdk/npm/prism-code/CHANGELOG.md).

Each entry uses the four headers [STABILITY.md](STABILITY.md) section 2 sets, in this order: Features Added, Breaking Changes, Bugs Fixed, Other Changes.
Breaking Changes is the per-version breaking log.
Before 1.0 a minor bump may break you and a patch bump never does; from 1.0 on, versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
The 0.1.0 entry predates this rule and keeps its original headers.

To move to 1.0, read the [migration guide](docs/site/migration/to-1-0.md).

## Policy

### Compatibility
- Holo/1 and accepted Prism application inputs remain stable. Additive contracts use new registered schemas; an incompatible schema change requires a new schema identifier and an explicit migration.

### Breaking Changes

* **holo:** holo v5 is a UORC archive named by κ (ADR-017) ([#663](https://github.com/UOR-Foundation/prismpm/issues/663))

- The proof statement's `timeVerified` is `SOURCE_DATE_EPOCH` when that is set, so the same inputs give the same statement bytes; otherwise it is the time of the run, as before.
- An integrity failure fails every policy, P0 included. The Rust verdict, `@prism-code/verify` and `prism-code check` add the reason `policy.integrity` with no level withheld whenever `holo.integrity` fails, so a damaged holo never passes a policy whose minimum is P0. The verdict golden `calculator.tampered-guest.json` gains the reason.

- `prismpm::holo::canonical::{encode_canonical, decode_canonical}` moved to `prismpm::holo::model_document`, since they validate the model document and the canonical value codec stays in `errors` (#448).
- `CanonicalDocument::parse` and `from_value` refuse the 19 contracts whose semantic checks belong to another module (SDK locks, acceptance records, browser receipts, native-library evidence, model documents) with PP9001. Parse them with the owner's `parse_contract`/`contract_from_value` (for example `prismpm::sdk::contract_from_value`), or with `prismpm::contract_owners::{parse, from_value}` when you hold only the id. The checks themselves are unchanged (#448, #449).
- `prism-code check` without a holo is removed (#584). It was the 0.2.0 spelling of `build --check`, announced as removed in 0.4.0 but still running through 0.7.2 with a warning that named that version. It is now a usage error (exit 64) that names `prism-code build --check`. Migration: replace `prism-code check [args]` with `prism-code build --check [args]`.
- `prismpm export-browser` and `verify-browser-publication` return `prismpm/browser-export/2` and `prismpm/browser-publication-integrity/2`, whose file lists hold exactly closure v1 (six files) or closure v2 (sixteen). Releases built now export sixteen files, so a consumer that pins the six-file closure or a `/1` receipt, such as a Pages publication contract, must move to closure v2. The `/1` contracts stay registered.
- A plain `prismpm build` of an application now needs a `prismpm/sdk-lock/2` or `/3` lock, because the provenance statement is derived from it (#268). An absent or `/1` lock is refused with `PP3018` before compiling; bind the SDK with `prismpm update --toolchain <digest-ref>`, migrate the lock, or pass `--no-provenance`.
- `experimental_pull` refuses a policy object with members a policy file cannot have (#292), such as `capabilities` or `replay`, with `policy.invalid`, because a pull's policy is what `check` reads. A `policy` that is not a string or an object, such as `null`, is refused the same way; `null` used to mean the default policy, P2. For a holo with an attestation section, the verdict's `holo` member is now the fingerprint of the file as given, as in `check`, and a statement line that cannot be read is reported as `pull.attestation` even when the policy would also fail.
- `experimental_verify`, `experimental_createClient` and `Application.experimental_verify` no longer take `statements` (experimental). Self-written statements with `envelope: { verified: true }` raised a holo from P0 to a passing P2 with no signature checked. They are now refused as an unknown option, `policy.invalid`. `check` with a signer still reaches P1 and P2 from the signed statements in the holo. `@prism-code/verify` keeps the option, for callers that check signatures against a trust root they hold.
- `prism-code run <holo>` no longer exits 1 for every failed verdict (#348): it exits with the code of the error that explains the verdict. A provenance, document or policy reason, which is every holo today, stays 1; a proof reason is 10; a world outside the grant is 2.
- Histories and replay (#284, `docs/proposals/284-histories-replay.md`, experimental). A history, `prism/history/1` (schema and types in `@prism-code/spec`), is the dispatches of one application in order with their recorded outcomes; acceptance vectors are its first source, and it can also record a refusal. `prism-code replay <history | dir>... --holo <holo>` and `prismpm replay` re-execute histories against a build and compare every outcome byte for byte: exit 0 unchanged, 1 diverged (`DeterminismViolationError`, `replay.divergence`, `PP5701`), 2 could not replay (`ReplayError`, `PP5706`). Both write a deterministic `prism/replay/v1` statement with `--statement`, also on a divergence: the guest as its subject, the model, every history's dual digest, the divergence count and the runtime. `prism-code history` writes a holo's vectors as a history, `prism-code run --record` records live dispatches, and `experimental_replay`, `experimental_recorder` and `Application.history` expose the same to code. `checkReplayStatement` in `@prism-code/verify` fails a statement from another guest or model or one that records a divergence, each withholding P3, so a changed model cannot reach it; `verify` joins it when it reads statements, after #267's wire model change, and until then every holo stays P0.
- A `VerificationError` with no verdict that reaches the top of `prism-code` exits 2 instead of 1 (#348), such as `attest` on a holo whose footer does not verify. `check` keeps 0, 1 and 2 unchanged.
