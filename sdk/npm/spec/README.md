# @prism-code/spec

The Prism formats as data: TypeScript types, JSON Schemas and WIT files.

A Prism application is built by [PrismPM](https://github.com/UOR-Foundation/PrismPM) into a holo, a content-addressed `.holo` archive.
This package states what a holo and its documents contain.
It holds no functions and has no dependencies.
Readers, such as [`prism-code`](../prism-code/README.md), implement it.

The design is [docs/proposals/263-spec-package.md](../../../docs/proposals/263-spec-package.md).

## Format revision

This package describes holo format revision **`2026-10-23`**.

A revision is a date, independent of the package version.
A reader lists the revisions it accepts, never a date range:

```js
import { FORMAT_REVISION, FORMAT_REVISIONS } from '@prism-code/spec';

const support = { accepts: ['2026-10-23'] };
FORMAT_REVISIONS['2026-10-23'].physicalVersion;   // 4
```

An archive does not carry its revision date.
A reader recognizes the revision by the identifiers in `FORMAT_REVISIONS`.
They are the physical version, section order, extension names and `schema` strings.
So every new revision changes at least one of them.

## The dependency rule

Every Prism package imports format types and constants from `@prism-code/spec`.
No package redeclares them.
This package depends on nothing and holds no functions.

`prism-code` 0.2.0 does not depend on this package yet.
That change is RT-01, [#276](https://github.com/UOR-Foundation/PrismPM/issues/276).

## What is in it

| Path | Contents |
| --- | --- |
| `constants.mjs`, `constants.d.ts` | The hand-written frozen constants: magic, version, section kinds, manifest bytes, extension names, the roles of the attestation and assurance schemas. |
| `index.mjs`, `index.d.ts` | The entry point. Generated by `npm run build` and not committed: the constants above plus `SCHEMAS`, `HOLO_SCHEMAS`, one `<NAME>_PREDICATE_TYPE` per predicate and the document unions, all found by reading the folders below. |
| `types/holo.d.ts` | The binary layouts: header, section table, application manifest, extensions, content blobs, HOLOVIEW, the guest exports. |
| `types/documents.d.ts`, `types/predicate-map.d.ts` | Generated by `npm run build` from the JSON Schemas and the predicate files. Not committed. |
| `types/attestation.d.ts` | in-toto Statement v1, `PrismDigestSet`, blob and OCI manifest subjects, and the DSSE envelope. |
| `types/attestation-bundle.d.ts` | The holo attestation section (#267): Sigstore bundle v0.3, verification material, in-holo statements, the OCI referrer layout. |
| `types/predicates.d.ts` | `PredicateMap` and the registry types. |
| `schemas/holo/` | The decoded header and table, application manifest, source manifest and application directory. |
| `schemas/documents/` | `prismpm/model-document/1` to `/6`, `prismpm/sdk-lock/1` to `/3`, `prismpm/model-provenance/1`, `prismpm/build-manifest/1`, `prismpm/browser-provenance/1`. |
| `schemas/attestation/` | in-toto Statement v1, the DSSE envelope and the Sigstore bundle of the attestation section. |
| `predicates/` | Per predicate `<name>-v<N>.json` (status, owner, description), `.d.ts` and `.schema.json`; the registry schema; `registry.json`, generated and not committed. |
| `worlds/core-wasm.wit` | The Core-Wasm guest contract `hologram:guest/core-wasm@1`. |

The model document and lock schemas are byte-identical copies of the repository's `schemas/` folder.
A test fails if they drift.

The tables of every schema (by `$id` and title) and every predicate are generated into the docs, not kept here: [API / Spec package](https://universal-coordinate-foundation.lovable.app/docs/api/spec-package).

## The holo in one table

Little-endian. Source: `Foundation.Holo.V1.Format` and `Foundation.Holo.V1.Wire`.

| Offset | Field |
| --- | --- |
| 0 | `HOLO` |
| 4 | u16 physical version, 4 |
| 6 | u16 flags, 0 |
| 8 | u16 section count, 8 |
| 10 | 8 rows of u64 kind, u64 offset, u64 length |
| 202 | section bodies, contiguous, in table order |
| end - 32 | BLAKE3 of every earlier byte, the archive fingerprint |

The rows are, in order: application manifest (15), source manifest (8), two extensions (14), four content blobs (16).
The content blobs are sorted by their `blake3:` label.

## Predicates

A predicate is four files in `predicates/`, and nothing else changes:

- `<name>-v<N>.json`: `status`, `owner` (`{ "issue": 266 }` or `{ "milestone": "..." }`) and `description`.
- `<name>-v<N>.d.ts`: its type `<Name>PredicateV<N>` and `export declare const <NAME>_PREDICATE_TYPE`.
- `<name>-v<N>.schema.json`: its schema, with `$id` `https://uor.foundation/prism/<name>/v<N>/schema.json`. A predicate without one has status `placeholder`.
- a fixture in `test/fixtures/predicates/<name>-v<N>/`.

The predicate type is `https://uor.foundation/prism/<name>/v<N>`.
`npm run build` writes `predicates/registry.json`, the `<NAME>_PREDICATE_TYPE` constants in `index.mjs` and `PredicateMap` in `types/predicate-map.d.ts` from those files.
The proof predicate is defined (`proof-v1`, issue [#266](https://github.com/UOR-Foundation/PrismPM/issues/266)); its design is [docs/proposals/266-proof-predicate.md](../../../docs/proposals/266-proof-predicate.md) and `test/fixtures/attestation/statement/calculator.json` is its calculator example.
`replay-v1` is a placeholder: its type is still `unknown`.
The type files are `.d.ts`, not `.ts`, because the package has no compile step.

## Adding a schema

A new schema is added by adding files, and no file that exists changes.
That is what lets two pull requests that each add a schema merge without a conflict.

- A document schema is `schemas/documents/<family>-v<N>.schema.json` with `properties.schema.const` set to the document's name, such as `prismpm/widget/1`. `SCHEMAS`, the `DocumentSchemaName` union, the `<Family>` union and `types/documents.d.ts` follow from the file.
- A holo section schema is `schemas/holo/<name>.schema.json`; its `HOLO_SCHEMAS` key is the file name in upper snake case.
- Any other schema goes in a folder under `schemas/`; it is reachable by its path through the `exports` map.
- Each schema has a fixture: `test/fixtures/<folder>/<name>/<case>.json` must validate, and `test/fixtures/<folder>/<name>/invalid/<case>.json` must be rejected. A schema with no fixture fails `test/schemas.test.mjs` by name. The few schemas from before this rule carry a `PENDING` file instead, to be deleted with their first fixture.

`exports` maps `./schemas/*`, `./predicates/*` and `./worlds/*` by pattern, so a new file is importable the moment it exists.
`test/new-schema-is-added-by-adding-files.test.mjs` proves both halves: every schema file resolves through the `exports` map, and a copy of the package gains a schema and a predicate while no existing file changes.

## Attestation subjects

Subjects follow ADR-015 from [#274](https://github.com/UOR-Foundation/PrismPM/issues/274).
A blob subject carries a `PrismDigestSet`: exactly `sha256` and `blake3`, over the same bytes.
For a content blob, `blake3` equals the blob's label without the `blake3:` prefix.
The footer is BLAKE3 of the body, not of the file, so it never appears under `blake3`.
A registry-facing statement adds `{ name: "oci-manifest", digest: { sha256 } }`.

## Versioning

The package is 0.x: a minor release may break, a patch release only adds or fixes.
The format revision changes independently of the package version.

## Tests

```
npm run build
node --test "test/*.test.mjs"
```

`npm run build` writes the generated files. `prepare`, `prepack` and `pretest` run it, and the tests build them themselves, so a fresh checkout needs no step.

The tests decode the reference archive with `prism-code`'s own reader, imported, not copied.
They validate every section and document against these schemas.
The reference archive is calculator-example's `artifacts/Calculator.holo`, SHA-256 `84371aaa...86e7`.
PrismPM's `prism-code` fixture is the same file.
