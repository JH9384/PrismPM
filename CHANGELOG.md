# Changelog

Every release of the `prismpm` crate and the SDK has an entry here, newest first.
The `prism-code` npm package has its own: [sdk/npm/prism-code/CHANGELOG.md](sdk/npm/prism-code/CHANGELOG.md).

Each entry uses the four headers [STABILITY.md](STABILITY.md) section 2 sets, in this order: Features Added, Breaking Changes, Bugs Fixed, Other Changes.
Breaking Changes is the per-version breaking log.
Before 1.0 a minor bump may break you and a patch bump never does; from 1.0 on, versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
The 0.1.0 entry predates this rule and keeps its original headers.

To move to 1.0, read the [migration guide](docs/site/migration/to-1-0.md).

## Policy

### Compatibility
- Holo/1 and accepted Prism application inputs remain stable. Additive contracts use new registered schemas; an incompatible schema change requires a new schema identifier and an explicit migration.

## [Unreleased]

### Features Added
- `prismpm check <path.holo> [--policy <file>] [--json]` (#270, experimental, `docs/proposals/270-check-rust.md`): the Rust half of the typed verdict. The holo is read through the modeled wire accessors and judged against a policy; the verdict is the `prism/verdict/1` of `prism-code check`, `holo.verify()` and `@prism-code/verify`, with the same check ids, order and withheld levels, held against the goldens the JavaScript CLI prints (AL-06). Exit 0 when the policy passes, 1 when it fails, 2 when no verdict was reached; with `--json` stdout holds exactly one canonical verdict on 0 and 1 and nothing on 2, and the exit 2 diagnostic is `PP5603` on stderr. The reader admits the attestation section of #267 and checks a proof statement with the checks of #266 (`PP5501` to `PP5507`), but verifies no signature until #272, so a present statement fails its envelope check and every holo is P0 today. `PP5601` (level below the policy minimum) and `PP5602` (world exceeds the granted capabilities) are registered. `prismpm check` without a holo still validates the project model. Conformance AL-03, AL-05 and AL-06.
- `prism-code dev [<dir>]` and the local studio (#288, `docs/proposals/288-prism-dev.md`, experimental): watches the model, rebuilds when the bytes of its sources change, judges the new holo with the `check` the command line runs, and serves a page on `http://localhost:4100` (`--port` moves it; a port in use is the error `dev.port`, never a silent move) with a Check tab (the verdict, the level, every reason, the time from the edit to the verdict) and a Replay tab, which says `unavailable` until `prism replay` reaches main and reads one file, `src/dev-replay.mjs`. The page is plain HTML with no framework, loads nothing from outside its origin, and judges the same bytes again with `@prism-code/verify`. A build that fails, or names no holo, leaves no current verdict. `--policy <file>` re-checks on an edit to the policy with no build; `--build <command>` and `--holo <path>` name a build of your own. `.github/workflows/dev-e2e.yml` measures edit to verdict with the real build and runs the page in a network namespace with only loopback.
- The second reference archive, Payment Approval (#278, part of M2 and #284): `examples/PaymentApproval` is a text application (`prismpm/text-application/1`, the profile `prism-code init` scaffolds) that decides a payment from a requester role, an amount and a limit, with nineteen acceptance vectors; its archive is committed as `sdk/npm/prism-code/fixtures/PaymentApproval.holo` beside the Calculator, with its inspection goldens and a `prism/history/1` history, and stays out of the npm package, whose size cap the Calculator alone nearly fills. `cargo xtask verify-examples`, the prism-code CI vectors step, and the reference-archive tests of `prism-code`, `@prism-code/verify`, `@prism-code/spec` and `prismpm inspect` now cover both archives.
- Policy files for `prism-code check` and `run` (#285, `docs/proposals/285-policy-file.md`, experimental): `--policy` takes a Rego file (`.rego`) or the name of a shipped policy. `default` (P2 or above, and the declared world within the granted capabilities) is now a file that goes through the same evaluator as a user policy, and `pure-only` and `provenance-only` ship beside it. A policy reads one versioned document, `prism/policy-input/1` (schema and types in `@prism-code/spec`), and decides with `minimum` and `deny`; it never changes the level and never lives in the holo. The evaluator in `@prism-code/verify` is a closed subset of Rego v1 with no dependencies, which refuses what it does not implement and whose answers are pinned against OPA; `parsePolicy`, `evaluatePolicy`, `policyInput` and `POLICIES` are exported. A policy that does not parse is `PolicyParseError` (`policy_parse_failed`) and one that cannot be evaluated is `PolicyEvaluationError` (`policy_evaluation_failed`), both exit 2; a denial is a verdict reason named by its rule, `PolicyDeniedError` (`policy_denied`), exit 1. CUE is not evaluated yet, and a `.cue` file exits 2. JSON policy files keep working. Every holo is still P0 until holos carry signed statements (#267, #268), so the default policy still fails every real holo.
- Containers in `prism-code` (#348, `docs/proposals/348-container-lifecycle.md`, experimental): one run of a holo is a container with Docker's states (`created`, `running`, `exited`), a start and finish time, an exit code and the returned output, kept until removed. `prism.containers.run(image, input)` returns it after it exits, `create` and `start` are the two-step form, `container.inspect()` reports `prism/container/1` with the state, the exit code and the image digest, and `rm: true` removes it on exit. `prism-code run <holo> <input>` (or `--input`) is the same lifecycle: stdout holds the output and nothing else, the process exits with the container's code, `--rm` removes it, and otherwise the record stays in `$PRISM_HOME/containers` (default `~/.prism/containers`) until `prism-code rm <container>`; `prism-code inspect <container>` reads it. `prism-code run <holo>` with no input still serves.
- `EXIT_CODES` and `exitCodeFor(error)` in `prism-code` (#348): 0 on success and a non-zero code for each `PrismError` subclass, the single table containers and the command line share. New codes: 10 `ProofMismatchError`, 11 `WorldMismatchError`, 12 `DeterminismViolationError`, 13 `ReplayError`.
- `@prism-code/conformance` (new package, not yet published, experimental, #287, `docs/proposals/287-conformance.md`): the executable suite every Prism runtime runs in CI through an entrypoint shim, `prism/conformance-shim/1`. Scenarios are data, with stable check ids, covering load, `verify` verdicts and typed errors, dispatch of the reference archive's acceptance vectors, capabilities deny by default, dual digests and the world contract, over a corpus of damaged archives derived from the reference and pinned by sha256. A runtime declares expected failures by check id, and the report distinguishes pass, fail, xfail, unexpected pass and not applicable. Replay checks are named placeholders until #284 merges. `prism-code` passes.
- `COMPLIANCE.md`: a matrix of feature by runtime (JavaScript, Rust, Python) with `+`, `-` and `N/A` cells, generated from the suite's results. `.github/workflows/npm-conformance.yml` regenerates it and fails when the committed copy is stale.
- The format-change gate: `.github/workflows/conformance-gate.yml` fails a pull request that changes the `.holo` format (the spec package's schemas or the Rust writer) without adding or changing a scenario. `CONTRIBUTING.md` says how to satisfy it.

### Breaking Changes
- `prism-code run <holo>` no longer exits 1 for every failed verdict (#348): it exits with the code of the error that explains the verdict. A provenance, document or policy reason, which is every holo today, stays 1; a proof reason is 10; a world outside the grant is 2.
- Histories and replay (#284, `docs/proposals/284-histories-replay.md`, experimental). A history, `prism/history/1` (schema and types in `@prism-code/spec`), is the dispatches of one application in order with their recorded outcomes; acceptance vectors are its first source, and it can also record a refusal. `prism-code replay <history | dir>... --holo <holo>` and `prismpm replay` re-execute histories against a build and compare every outcome byte for byte: exit 0 unchanged, 1 diverged (`DeterminismViolationError`, `replay.divergence`, `PP5701`), 2 could not replay (`ReplayError`, `PP5706`). Both write a deterministic `prism/replay/v1` statement with `--statement`, also on a divergence: the guest as its subject, the model, every history's dual digest, the divergence count and the runtime. `prism-code history` writes a holo's vectors as a history, `prism-code run --record` records live dispatches, and `experimental_replay`, `experimental_recorder` and `Application.history` expose the same to code. `checkReplayStatement` in `@prism-code/verify` fails a statement from another guest or model or one that records a divergence, each withholding P3, so a changed model cannot reach it; `verify` joins it when it reads statements, after #267's wire model change, and until then every holo stays P0.
- A `VerificationError` with no verdict that reaches the top of `prism-code` exits 2 instead of 1 (#348), such as `attest` on a holo whose footer does not verify. `check` keeps 0, 1 and 2 unchanged.

Deny by default holds twice: `prism/capabilities/1` gains the kind `providers` (`allow-providers`, `deny-providers`), checked for every declaration before any provider starts, and a returned variable is produced only when the `variables` kind allows it, otherwise it is withheld and reported by name. Failures are `CapabilityDeniedError` (`capabilities.providers`), `ProviderNotFoundError`, `ProviderReplyError` and `ProviderFailedError`, and none quotes a reply line. `prism-provider-kv`, a local key-value store kept as one JSON file, ships as a package binary and is the reference provider. `@prism-code/verify` accepts the new set members. The plugin scan now skips names starting with `provider-`. Nothing inside a holo can read these variables yet, because the guest world imports nothing and `prism-code run` does not read `prism.toml`.
- Runtime middleware in `prism-code` (#295, experimental, guide `docs/site/guides/write-a-middleware.md`): `Application.experimental_middleware` is a stack of named, tagged middleware over the four steps the runtime performs, `verify`, `instantiate`, `dispatch` and `record`, ordered by step, by `priority` and by `addRelativeTo` before or after a named middleware, with `remove`, `removeByTag`, `override`, `clone` and `use(pluggable)` after the AWS SDK for JavaScript v3 stack. Each step wraps one operation of its own, so `instantiate` is where a capability check can link imports. A middleware that throws anything but a `PrismError` raises the new `MiddlewareError` (`middleware_failed`); stack misuse fails with `middleware.step`, `middleware.name`, `middleware.relative` or `middleware.shape`. Tracing ships as the first middleware: `experimental_tracing({ tracer })` opens one OpenTelemetry span per step, `prism.<step>`, from a tracer the caller passes, so the package still has no dependencies. `runGuest` is unchanged.
- `prism-code generate <holo> --out <dir>` (Part of #289, experimental): bindings and a typed client from the holo's WIT world and model, as ES modules with TypeScript declarations that import nothing. One code model feeds one writer per language; JavaScript is the first, Rust and Python follow. `world.js` binds `hologram:guest/core-wasm@1` from its WIT file (vendored, checked against the world's digest); the client has one method per modeled operation and a typed error with the guest's codes, or `invoke(bytes)` when the model has none. The output directory is required. `prism-generate.json` records the language, the generator, the world and the model (shaped like the lock's `inputs.world` and `inputs.model`) and each file's sha256, so a second run with the same inputs writes nothing; a file `generate` did not write is never overwritten.

### Breaking Changes
- `prism-code run` gates on `check` (#282, `docs/proposals/282-run-gated-on-check.md`, experimental, breaking): the holo is judged against the policy (`--policy`, default P2) with the capability set it will run under before it is instantiated. A failing verdict refuses with exit 1 and prints the verdict; no verdict refuses with exit 2. `--allow-unverified` runs it anyway with a warning on every start and is never the default. Every holo is P0 today, so `run` without a policy that accepts P0 or the flag now refuses. A policy's new `effects` member lists the impure effects the world may import; `[]` is the pure-world policy, reported as `policy.effects`.
- A guest that declares an import now fails to load with `CapabilityDeniedError` (`capability_denied`, check `capabilities.import`) instead of `PrismCodeError` `core.imports` (#279); the `prism-code` exit code stays 2.
- `prism-code inspect` on a `.holo` prints the human inspection instead of the 0.2.0 JSON summary, and `--json` prints `prismpm/holo-inspection/1`. A closure directory keeps the 0.2.0 summary.
- `prism-code check <holo>` judges the holo and returns a verdict instead of running `prismpm check` in the SDK image; the Docker-backed check is now `prism-code build --check` (#270).

### Bugs Fixed
- `prism-code attest --key` writes an empty DSSE `keyid`, so `cosign verify-blob-attestation` accepts the bundle (#292): cosign skips a signature whose `keyid` is not its own, and the key's hash there made such a bundle verify nowhere but in `prism-code`. The hash stays in `verificationMaterial.publicKey.hint`, and bundles already written still verify in `prism-code`.
- Keyless `prism-code attest` no longer fails intermittently with `(409) an equivalent entry already exists` from the public Rekor log. It waits 30 s for each Sigstore service instead of 5 s, so a slow answer is not re-sent, and when a re-sent entry is still refused as a duplicate it signs once more. The unused first entry stays in the log.

### Other Changes
- `signatures[].sig` may be empty in `dsse-envelope.schema.json` and `sigstore-bundle.schema.json` (#268): the unsigned provenance placeholder carries one empty signature, which no verifier accepts. Every bundle that was valid stays valid.
- Spec pull requests no longer conflict (#340): the docs pages (`docs/generated/`) and the spec pin (`sdk/docs/spec.lock.json`) are no longer committed, `node sdk/docs/generate.mjs verify` generates the docs from the checkout and fails naming the page when generation, an example or the vocabulary lint fails, and the spec package's `index.mjs`, `index.d.ts`, `types/documents.d.ts` and predicate registry are generated by `npm run build` from the files in `schemas/` and `predicates/`, so a new schema is added by adding files only. The hand-written constants moved from `index.mjs` and `index.d.ts` to `constants.mjs` and `constants.d.ts`; `@prism-code/spec` imports are unchanged.
- `prism-code check` without a holo, the 0.2.0 spelling of `build --check` (#270). It still runs `prismpm check` in the SDK image and prints a warning; it is removed in 0.4.0. Migration: replace `prism-code check [args]` with `prism-code build --check [args]`.
