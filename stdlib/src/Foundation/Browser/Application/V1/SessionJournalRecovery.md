# Private journal recovery

DK-30 component; not authentication, execution freshness, durable acceptance or
public application admission. DK-26 and its late-completion refusal are unchanged.

`sourceRecoveryContextBytes` consumes the complete canonical `[1,0,state]`
Session success frame and validates the original state. It returns
`[1,4,[binding,limits,manifest,durable,[execution,nextEffect,selector]]]`.
Only phase, revision and presentation are omitted. Pending-command authority
references retain the exact compact Session grammar. The SDK hashes these actual
generated bytes; a caller-supplied context or a normalized pretend state is not
equivalent. The existing frame has no additional wrapper-byte overhead.

`sourceRecoveryWireBytes` consumes
`[1,[1,state,newAuthority,newExecution,newSelector,newPresentation]]` and returns
the existing Session success/error family. A valid Ready or Closed state must have
no pending command. Replacement authority has the same principal and scope,
nondecreasing epoch and the original evidence bound. All other durable fields,
binding, limits and manifest remain unchanged. A different 32-byte execution,
bounded selector and valid Ready presentation reset effect/revision counters.
Execution inequality is not freshness; the journal must verify its actual witness.
Whole canonical requests/replies remain at most 64 MiB, with a 1-GiB Wasm ceiling.
Frames are not nested and no independently legal field is silently clamped.

RecoveryReady requires authenticated current Closed/no-pending journal state.
RecoveryTerminal requires authenticated Unknown/Closed pending state, the exact
original signed Prepared anchor and a genuine independently authenticated terminal
receipt. Current and Prepared generated context bytes must match. The unchanged
Session settle operation runs against Prepared, never the Closed/Unknown state;
the recovery operation consumes that exact quiescent successor. Unknown results
cannot settle and no recovery path reruns an effect.

The metadata plan must bind separate immutable descriptors for the settle and
recovery frames, their exact predecessor/successor linkage, current state, Prepared
anchor and actual terminal receipt. This avoids two nested maximal state frames.
Source wrappers independently admit replacement authority and domain transitions;
the real journal verifies signature ownership, descriptor chains, freshness and
atomic head replacement. Typed fields, equal hashes or signatures alone cannot
establish those external facts. Missing proof leaves the operation unresolved.

Full DK-30 acceptance remains red until generated native/Wasm bounds, actual
source mutations and authenticated host/recovery/retirement/witness owners pass.
